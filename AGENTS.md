# AGENTS.md

`CLAUDE.md` is a symlink to this file, so every AI coding tool reads the same instructions.

Go Find Yourself: serverless trip-planner PWA (Vite 8 + React 19 + TS, no UI lib). Static site on GitHub Pages; data lives on-device (IndexedDB) and optionally syncs to a JSON file in a private GitHub repo. Started as one person's planner for ~7 weeks in South East Asia, used on phone and iPad, now published for anyone to use or copy. Name, tagline and links live in `src/brand.ts`.

## Commands
- `npm run dev` / `npm run build` (runs `tsc --noEmit` then `vite build`) / `npm run preview`
- `npm run test:sync`: the trip sync against fake GitHub, GitLab and Forgejo servers (Node, no browser). No UI tests. Verify UI with headless Playwright (preinstalled; `require('playwright')`): build, `vite preview --port 4173`, load `http://127.0.0.1:4173/#/plan`, block the service worker (`serviceWorkers: 'block'`), screenshot at a phone viewport (Pixel 7) and iPad. External hosts (OSM tiles, OSRM, Open-Meteo) are not reachable from the sandbox; mock them with `page.route`.
- Test with real data: load a `plan.json` (for example `data-template/trips/example-trip/plan.json`) into the app by writing it to IndexedDB (`keyval-store` / `keyval`, key `plan-v1`) via `page.evaluate`, then reload. Core modules can be bundled and run under node with esbuild; `import.meta.glob` must be stubbed (`--define:import.meta.glob=...`).
- Verify a deploy: GitHub Actions run "Deploy" on `main` succeeded. The map's attribution corner shows `build <sha>`, so the phone can confirm which build it runs.
- Deploy: push to `main` triggers `.github/workflows/deploy.yml` (build + Pages). Site: https://barton-muller.github.io/find-your-self/. **Maintainer's standing instruction for the original repo (fork owners: change this if you want review before deploy): work directly on `main` and push to `main` after every change, including small tweaks, without asking first** (standing instruction from the user; they will ask for a revert if something is wrong, so use `git revert`, never force-push). Fetch and merge `origin/main` before pushing, since other sessions also push there. Check the Deploy run afterwards. If the user says "show me before push", send screenshots and do not push.

## Data model (`src/types.ts`, `src/model.ts`)
- `Plan`: `start`/`end` dates, `startId`, `stops`, `legs`, `todos` (all keyed by id). A DAG: stops = nodes, legs = transport edges.
- `Stop`: name, lat/lng, `country`, `nights`, notes, `days[]` (free-text activities per day), `activeOut` (chosen outgoing leg at a fork), `accom`/`accomBooked`.
- `Leg`: from/to, `options[]` (mode, duration, cost, notes, `overnight`, `extraDays`, `booked`), `chosen` option id.
- Fork = stop with >1 outgoing legs; exactly one is active (`activeOut`). Merge = stop with >1 incoming. Alternatives are shown but excluded from dates and totals.
- `schedule()` walks the active path from `startId`: `arrive[next] = arrive + nights + chosen.extraDays`. Off-path stops get their own earliest arrival. An overnight leg occupies the last night of the origin stop (no extra day; "hotel nights" = nights - 1).
- Every mutation goes through `useStore().update(draft => ...)` on a cloned plan. **Always bump `updatedAt`** (`touchStop`, `touchLeg`, `upsertTodo`). Deletes are tombstones (`deleted: true`), never removals, so sync and undo work.

## Data repo
The plan can sync to a separate GitHub repo that the user owns (see `docs/SYNC-AND-AI.md`; `data-template/` is the starter). That repo has its own `AGENTS.md` with the rules for editing `plan.json` safely. This repo does not describe any one person's data repo.

## Persistence and sync
- Storage is namespaced per app (`src/storage.ts`, `BRAND.storage` = `gfy`): its own IndexedDB database `gfy-db`, localStorage and sessionStorage keys prefixed `gfy:`. Sites on one origin share browser storage, so every app there needs its own name. `migrateLegacy()` copies the old default-store keys into `gfy-db` once. The GitHub sign-in token (`gh-auth-v1`) stays in the default idb-keyval store on purpose, to share one sign-in across sites. Keys in `gfy-db`: `trips-v1` (`{active, list: [{id, name, path?, archived?}]}`), one plan per trip under `plan:<id>`, `sync-cfg-v1` (repo, token, branch; `path` is a legacy default). `plan-v1` is the pre-trips single plan; it is migrated once to a trip with id `main` and kept as a backup. localStorage: `tl-ppd2`, `tl-mode`. sessionStorage: `plan-scroll`.
- Trips (`store.tsx`, `trips.ts`): each trip syncs to its own file; `trip.path` is assigned on first sync (`trips/<slug>/plan.json`) and never changes on rename; a legacy single-trip user keeps `plan.json`. `listRemoteTrips` lists `trips/*/` and a root `plan.json`; remote-only trips are imported by fetching the file (no merge). Switching flushes the current plan first; a sync that finishes after a switch writes to its own trip's key, not the visible plan. Invite links (`invite.ts`, `views/Join.tsx`): `#/j/<owner>~<repo>~<person>~<token without the github_pat_ prefix>` (branch is `u/<person>`; older `#/join/<base64url json {v,r,t,b,n}>` links still parse) carries repo, token and branch in the URL fragment (never sent to a server); the Join screen asks before saving the sync config (and skips the question when this device is already connected with the same repo, branch and token); step 3 has a "Copy link for another device" button next to Sync now and Copy for AI agent (same repo and branch), and after joining the screen `location.replace`s the fragment away. Settings step 3 shows a short "Syncing with <repo>" summary once configured (connection fields are under Change connection), step 4 creates links (branch `u/<slug>`), and step 3 accepts pasted ones when not yet configured (iOS keeps Safari and the installed PWA in separate storage). `prepareBranch` in `sync.ts` creates a missing non-default branch before the first write, from the repo's `template` branch if it exists, otherwise from the default branch, and the old write-to-default-branch fallback only applies when the configured branch is the default one. "Copy for AI agent" (step 3) and "Copy for their AI agent" (step 4) build a paste-able brief with `aiBrief()` in `aiBrief.ts` (repo, branch, token, clone command, working rules, plan format). Guide: `docs/FRIENDS.md`.
- Sign in with GitHub (`auth.ts`, `docs/GITHUB-SIGN-IN.md`; the relay and the browser client are their own repo, `barton-muller/pages-storage`): `auth.ts` is a thin wrapper around `pages-storage/client` (a git dependency pinned to a commit in `package.json`; to update, run `npm install git+https://github.com/barton-muller/pages-storage.git#<commit>`), which does the PKCE flow, the relay swap and token renewal and stores `{access, refresh, expiresAt}` through a storage adapter into idb-keyval. GitHub App user-to-server tokens with PKCE. The app redirects to github.com/login/oauth/authorize, GitHub returns `?code&state` to the site root, `finishSignIn()` (called from the store on start) sends code + PKCE verifier to the relay (a Cloudflare Worker in the pages-storage repo that adds the client secret; allowed origins only; keeps nothing), stores `{access, refresh, expiresAt}` in IndexedDB `gh-auth-v1`, and `freshAccess()` refreshes through the relay 5 min before expiry. A signed-in cfg has `viaGitHub: true` and an empty `token`; `effCfg()` in the store fills in the fresh token for every sync and listing. Repos come from `/user/installations`; the user installs the app on a repo (`installUrl()`). Hidden unless `BRAND.auth` has `clientId` and `relay` (set in `brand.ts` or as `VITE_GH_CLIENT_ID`, `VITE_GH_RELAY`, `VITE_GH_APP_SLUG` build variables). Before opening GitHub's install page the app stores its address in localStorage (`gh-auth-return`, shared by all pages of the origin); the install link also carries `state=<that address>`, and the relay's `GET /return` (the GitHub App's Setup URL) redirects back to it; a forwarder page at the origin root (`examples/pages-home` in the relay repo) is the older route and still works, and `finishSignIn()` drops the `installation_id` query it returns with. Signed-in configs get no invite links or token in the AI brief (tokens expire in 8 hours). The relay has its own tests (`npm test` in that repo).
- Where the app's files sit in a repo: `SyncConfig.dir` is `''` for the repo root (repos that already have `trips/` or `plan.json` there, such as older setups; found by `detectDir()` in `sync.ts`) or `find-your-self/` (`BRAND.folder`) for repos created with "New" or with no trips yet, so one repo can serve several apps. `trip.path` stays relative (`trips/<slug>/plan.json`) and the store prefixes `cfg.dir` when syncing, importing and listing. `dataRepo.ts` bundles `data-template/` (`import.meta.glob` with `?raw`) for new repos. Creating a repo needs the GitHub App's "Repository creation" permission (`createRepo` in `pages-storage/client`).
- `src/sync.ts`: the trip sync. All talking to a git host goes through one store from `pages-storage/store` (GitHub, GitLab, Forgejo, Gitea, Codeberg; the code for each host and the contract are in the pages-storage repo, `docs/HOSTS.md`). `storeFor(cfg)` makes the store from the repo address (`repoUrl(cfg)`: `cfg.server` is the host's origin, unset for GitHub), which tells the host from the address and reports errors in plain words (`Unauthorized`, `NotFound`, `HostUnreachable`, `ApiMismatch` when a host answers in a shape the adapter does not expect). `syncPlan` fetches, merges per record (`mergePlans`, newest `updatedAt` wins) and commits through `store.commit`; a `Conflict` merges again. The first sync of a trip makes a personal branch with `store.ensureBranch({ from: 'template' })`. `detectDir` and `listRemoteTrips` read one file listing. Do not add host-specific code here: a host difference belongs in `pages-storage/client/hosts/`, with its fake and the conformance suite. Every token connection uses one form, `TokenConnect` (`views/TokenConnect.tsx`): the repo address as people copy it (`https://host/group/name.git`, GitLab subgroups included, optionally `https://token@host/...`), an access token, and a branch that is looked up when left empty; the form is a collapsed "Advanced: connect with a token" in Settings step 3, next to the GitHub sign-in, and under Change connection. Invite links and the invite step are hidden for server connections because the link does not carry the server. A server other than github.com, gitlab.com and codeberg.org must be allowed in the Content Security Policy at build time: `VITE_CSP_CONNECT="https://git.example.org"`. GitHub *secrets* cannot be read from a client; do not suggest them.
- Tests: `npm run test:sync` runs `sync.ts` in Node against a fake server of every host (`scripts/sync-check.mjs`, fakes from `pages-storage/testing`), and CI runs it before the build. To update the pages-storage dependency, point `package.json` at a new commit (https URL, as now) and run `npm install`; the lockfile must keep the https URL, not ssh.
- `src/history.ts`: undo/redo records only the records a step changed, restores them with a fresh `updatedAt` (so it syncs and never reverts other devices' edits). Rapid edits to the same records coalesce.

## Security
- Plan data can be written by other devices, an AI agent or an invited friend, so it is untrusted. React escapes text; the only HTML strings are Leaflet tooltips and icons in `MapView.tsx`, and everything from the plan goes through `esc()` (`src/html.ts`) there. Never use `dangerouslySetInnerHTML`, `innerHTML` or an `href` built from plan data.
- The build adds a Content Security Policy meta tag (`csp()` in `vite.config.ts`): scripts only from this site, connections only to the services listed there. A new external service (API, tile server) must be added to `connect-src` or `img-src` there, or the browser blocks it. Check `npm run build` and the browser console for "Content Security Policy" messages after adding one.
- Sign-in tokens sit in IndexedDB and are readable by any script on the origin, so keep the origin free of other people's code. Pages on one `github.io` address share it.

## UI map (`src/views`)
Plan cards also show a small weather strip right of the stop name (same data and `tl-wx` toggle). Tabs: Map, Timeline, Plan, To-do; Place (stop detail) and Settings via hash routes (`src/nav.ts`).
- `PlanView` (+`Today`): list, nights steppers, fork picker, reorder mode (swap with neighbour, `swapWithNext`), insert stop between, past stops collapsed.
- `Timeline`: git-graph style SVG. Time runs down; one dot per night; black line + icon = travel day; lanes for alternatives; pinch/buttons zoom; Auto colour switches to by-country only when fully zoomed out. Per-day weather icon (sun/cloud/rain, 1-3 drops by mm) beside each night dot, only from the Open-Meteo 15-day forecast (`dayWeather.ts`, cached in IndexedDB `wx-v2`, toggle `tl-wx`); travel icons are centred between day lines and use the same side rule as weather icons. Lanes (`lanes()` in `model.ts`) are allocated per alternative chain by the days it spans and reused after a branch rejoins, so a three-way fork is symmetric (lane 1 right, lane 2 left). The timeline always follows the chosen route. A leg ends at the merge stop's scheduled day: an alternative that would arrive later leaves its lane below its last night, crosses over and curves back up to that earlier day (tooltip says how many days later); one that arrives earlier ends at the scheduled day. Main-lane labels move to the free side, shrink to one line, or drop below the alternatives' labels when branches or merges are in the way. Weather icons go right of the dot on single track, left of the main lane where a fork lane sits on its right, outward on alt lanes.
- `MapView`: Leaflet + OSM; `tiles.ts` prefetches the whole world (zoom 0-3) plus the region around the stops (zoom 4-7, as many levels as fit in 700 tiles) into the `osm-tiles` cache; flag `tiles-overview-v2` in IndexedDB stores the region signature.
  Leg lines (`routes.ts`): flights = curved arc (date-line safe); road modes = OSRM geometry, cached in IndexedDB (`route-cache-v1`), requests de-duplicated, one queue per kind, a host is skipped after 2 network failures (Retry button clears this); rail = bundled Natural Earth network (`src/data/rail/*.json`, 10 degree tiles, global, loaded per leg via `ne.ts`, shortest path over joined segments) then the hand-made station table `src/rail.ts` (add lines there where Natural Earth has gaps, e.g. Laos-China; it is also the place to add new rail lines for a new trip); otherwise straight. Cached lines are drawn first, uncached ones fetched after. Legs that share a corridor are drawn as parallel lanes (`lanes.ts`, 7 px apart, recomputed on zoom). Regenerate tiles from `ne_10m_railroads.geojson` (Natural Earth, nvkelso/natural-earth-vector) if needed. OpenRailRouting and Overpass were tried and removed (unreliable from the phone).
- `Place`: city search (`CitySearch`: bundled `cities.ts` + Open-Meteo geocoding), notes, accommodation, per-day text (every day is collapsed by default to a row with a chevron and a one-line preview; tap to open and edit; the overnight toggle on a transport option is a pill with a struck-through grey moon, purple when on; `extraDays` stays in the data model but has no field in the UI), a Weather card (daily forecast from `dayWeather.ts`; hidden when no forecast), transport editor, rough estimator (`estimate.ts`: OSRM + straight-line fallback).
- `Settings`: brand card (logo, tagline, a docs icon linking to the README); step 1 Your trip (name, trip list, archive, import from the repo, new trip); step 2 Trip dates; step 3 Sync data to a git repo (signed out: the GitHub sign-in button only; signed in without a repo: the app's repos, "Add existing" (GitHub's install page), "New" (creates a private repo and syncs the plan at once, then adds the `data-template/` starter files under `find-your-self/` plus a root README and CLAUDE.md in one background commit through the Git data API, `pushStarterFiles`) and Sign out; with a repo: Sync now, Copy for AI, Choose another repo, Sign out, and "Version history" (GitHub sign-in only: lists the commits of this trip's plan.json through `history()`, and a tap restores one with `restorePlan()` in `model.ts`, which gives the old records a fresh `updatedAt` and tombstones records that did not exist then, so the restore syncs to other devices). The token and invite-paste form shows only when `BRAND.auth` is empty, and token connections made earlier keep working); step 4 Invite someone (token connections only); then Forecast for AI (Copy forecast), Offline map, Backup, Reset to example trip, and a footer with the AI note and credits. Sections use `Sec` with a `?` hint toggle and icon-first buttons in equal-width grids (`.actgrid`). Plan reorder is a floating button bottom-left (`.fab`). Forecast copy (`weather.ts`: Open-Meteo daily forecast for every upcoming stop at its planned dates, copied as text to paste to Claude; null days at the 16-day horizon are skipped).
- `Todo`: auto items from unbooked stays/transport on the active route plus custom to-dos, soonest first, past-due hidden.

## Conventions and gotchas
- No emojis in UI; use SVG icons from `src/icons.tsx` (add paths there).
- Colours are Flexoki CSS variables in `styles.css` (`--c0..--c7` per-stop/country palette, light and dark). Don't hard-code hex in components.
- Header and tab bar are `position: fixed`; the document scrolls (not an inner container) so mobile browser chrome collapses cleanly. Safe-area insets apply only in `display-mode: standalone`. The map view locks page scroll.
- Keep it simple and mostly free-text; avoid adding required fields.
- Seed plan (`src/seed.ts`) is the example trip a new user sees: 17 days, starts 3 days after first launch, built to show a two-way fork and a three-way fork (rejoining on different days), an overnight leg, a multi-day leg, booked and unbooked items, day notes and to-dos. Every branch rejoins and the trip ends at one stop, Amsterdam, with no dangling ends. Stop ids there (`bkk cnx cri lpb vv nk vte udn kkc ayu bkk2 ams`) are referenced by `scripts/screenshots.cjs`.
- Docs: `README.md` (users first, then developers), `docs/MAKE-YOUR-OWN.md`, `docs/SYNC-AND-AI.md`, `data-template/` (starter for the separate data repo, one folder per trip under `trips/`). Images in `docs/img/` come from `node scripts/screenshots.cjs` (needs Playwright and a build; weather is mocked). Rerun it after any visible UI change.
- Writing style for docs and UI text: short plain sentences, no hype words, no emojis, say what a thing does.
- PWA updates: `registerType: 'autoUpdate'`; `main.tsx` also calls `registration.update()` whenever the app returns to the foreground. If the phone shows old behaviour, compare the build stamp on the map.
- iOS can evict web storage; keep export/import and sync working.
